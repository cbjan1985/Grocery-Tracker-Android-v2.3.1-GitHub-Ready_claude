# Grocery Tracker Android v2.3.1 — Designed by CB

This is the **mobile app source project** for Grocery Tracker. It uses Capacitor to package the existing v1.7 web-app logic as an Android application. The HTML file is an internal app asset under `www/`; the intended deliverable is the Android APK generated by the included GitHub Actions workflow.

## v2.3.1 changes

- Bundles SheetJS into the Android app during the build so `.xlsx` and `.xls` import/export work without a network connection after installation.
- Adds Excel export for inventory, to-buy list and purchase history, plus generated Excel import templates.
- Adds native Android save/share handling for JSON, CSV, Excel and PDF exports using Capacitor Filesystem and Share. On Android, the share sheet lets the user save the file to a location/app supported by the device.
- Keeps JSON backup/restore and local device storage. Import is previewed before applying.
- Adds native splash-screen configuration and launcher/splash assets using the existing CB logo.
- Refines mobile spacing and controls for a cleaner, compact interface.
- Updates the version to **2.3.1** (Android `versionCode 24`).

## Data and privacy model

- No backend and no live synchronization. App data stays on the device in WebView local storage until the user exports a backup.
- JSON backup/restore carries inventory, medicines, stationery and purchase history. CSV and Excel imports/exports are supported for supported data lists.
- The phone app and browser app use the same data structure, but they do not sync automatically. Transfer data using a JSON backup file.

## Known limitations (not falsely marked as fixed)

- Kannada translation for names not found in the built-in catalog still needs a translation service. The previous `window.claude` runtime is not available in the standalone phone app, so unknown names may remain without a Kannada translation; users can use the built-in catalog or add translations through supported app fields.
- Bill-photo reading is unavailable in this Android build because it depended on the unavailable Claude-only runtime. Use the purchase-list import instead.
- Native export opens Android's Save/Share chooser rather than the browser-only `showSaveFilePicker` interface.
- Live sync across devices is not provided because there is no server/backend.

## Build APK

The build runs on GitHub Actions; Android SDK/Gradle are not installed in the current authoring environment, so an APK was **not compiled or device-tested here**.

1. Extract the source ZIP and upload its contents to a GitHub repository (include `.github/workflows/android-debug.yml`).
2. In repository Settings → Actions → General, enable read/write workflow permissions so the release step can publish the APK. If you do not want GitHub Releases, remove the `Publish versioned APK release` workflow step; the workflow artifact remains available.
3. Open Actions → **Build Grocery Tracker Android APK** → **Run workflow**.
4. Download `Grocery-Tracker-Android-v2.3.1-APK` from the run artifacts, or download the APK from the versioned prerelease.
5. Install it on the Android device and test the checklist below.

The workflow installs the npm dependencies, copies the SheetJS distribution into `www/vendor`, bundles the native bridge, generates launcher/splash assets, creates/syncs the Capacitor Android platform, sets `versionCode 24` and `versionName 2.3.1`, and assembles the debug APK.

## Device test checklist

- [ ] Cold-launch native splash appears and fades into the app.
- [ ] Add inventory data, close/reopen app, and confirm data persists.
- [ ] Export a JSON backup through Android's share/save chooser; restore it and confirm inventory, medicines, stationery and purchase history return.
- [ ] Import CSV and Excel inventory files; confirm preview and cancel/confirm paths.
- [ ] Export inventory, to-buy list and purchase history to CSV and Excel while offline.
- [ ] Export to-buy list PDF and save/share it.
- [ ] Test partial purchase: plan 5 units, record 2 bought, confirm inventory increases by 2 and 3 remain on the purchase list.
- [ ] Confirm unsupported bill reading gives a clear message and does not pretend it succeeded.

## Upload to GitHub (quick steps)
1. Create a new GitHub repository (private is fine, no README).
2. Extract this zip. Show hidden files (Windows: File Explorer > View > Show > Hidden items; Mac: Cmd+Shift+.) so you can see the `.github` folder.
3. In the repo click **uploading an existing file**, drag in **everything inside** the extracted folder, commit to `main`. If `.github` does not upload, use **Add file > Create new file**, name it `.github/workflows/android-debug.yml` and paste `WORKFLOW_COPY/android-debug.yml`.
4. Settings > Actions > General > Workflow permissions > **Read and write permissions** > Save.
5. Actions > **Build Grocery Tracker Android APK** > Run workflow. After about 5-10 minutes download `app-debug.apk` from **Releases** (right side of the repo page) or from the run's **Artifacts** (bottom of the run page).
6. If the run shows a red cross, open the failed step and send the last 30 lines.
